# ToolMind - Tool-Using LLM Agent

![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![LLM](https://img.shields.io/badge/LLM-Google%20Gemini-4285F4)
![Validation](https://img.shields.io/badge/validation-Pydantic-e92063)
![Tests](https://img.shields.io/badge/offline%20tests-32%20passing-brightgreen)
![License](https://img.shields.io/badge/license-MIT-lightgrey)

ToolMind is an LLM agent that plans multi-step tasks and completes them by calling tools: **web search, calculator, read-only SQL queries and a sandboxed file reader**. Every call goes through argument validation, retries with exponential backoff and a loop guard, the whole run is bounded by a **step limit**, and **every reasoning step and tool call is logged** to JSONL.

## Features

- **4 tools** with automatic tool selection through Gemini function calling
- **Argument validation** with Pydantic; errors go back to the model so it can correct itself
- **Retry on failure**: exponential backoff for transient errors only (network, timeout, locked DB)
- **Step limit** (`MAX_STEPS`, default 8) with a graceful stop message
- **Loop guard**: the third identical tool call in a run is blocked
- **Full JSONL logs**: thoughts, tool calls, every attempt, retries, results, errors, token usage and timing
- **Defence in depth**: SQL validator + read-only connection + SQLite authorizer; file access confined to `data/`
- **Two test suites**: 32 offline tests (no API key needed) and 13 live multi-step tasks with automatic pass/fail checks
- Replies in the language of the request (English or Roman Urdu both work)

## Architecture

<p align="center">
  <img src="docs/architecture.png" alt="ToolMind architecture" width="900">
</p>

1. The task, a system prompt (rules, DB schema, list of data files) and the tool declarations are sent to the LLM.
2. The LLM answers, or requests one or more tool calls.
3. Each call is checked: the tool exists, the arguments pass the Pydantic model, and the call is not an identical repeat.
4. Valid calls run with retries; failures become an error message for the LLM.
5. The result is added to the conversation and the loop continues until a final answer or the step limit.

## Tools

| Tool | What it does | Safeguards |
|---|---|---|
| `web_search` | Current or external facts via DuckDuckGo (`ddgs`) | 1-10 results, trimmed snippets, network errors retried |
| `calculator` | Exact math, percentages, conversions | `simpleeval` (no `eval()`), whitelisted functions, `^` mapped to `**` |
| `db_query` | Read-only SQL on `company.db` (`employees`, `sales`) | One SELECT only, no comments, read-only connection, authorizer, max 50 rows |
| `file_reader` | Reads `.txt .md .csv .json .pdf` | Confined to `data/`; `../` and absolute paths denied; output size capped |

## Installation

```bash
git clone https://github.com/faizanjutt473/ToolMind-Agent.git
cd ToolMind-Agent

python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Linux / macOS

pip install -r requirements.txt
python setup_data.py           # creates data/company.db, sales.csv, notes.txt
```

Create a free API key at [Google AI Studio](https://aistudio.google.com/apikey), copy `.env.example` to `.env` (`copy .env.example .env` on Windows) and paste the key.

### Configuration (`.env`)

| Variable | Default | Meaning |
|---|---|---|
| `GEMINI_API_KEY` | - | Your Google AI Studio key (required) |
| `GEMINI_MODEL` | `gemini-3.5-flash` | Model name. Run `python main.py --list-models` to see valid names |
| `GEMINI_INCLUDE_THOUGHTS` | `true` | Log Gemini's thinking summaries |
| `GEMINI_TEMPERATURE` | model default | Optional override |
| `MAX_STEPS` | `8` | LLM calls allowed per task |
| `TOOL_MAX_ATTEMPTS` | `3` | Attempts per tool call (first try + retries) |
| `TOOL_RETRY_BASE_DELAY` | `1.0` | Seconds; doubles after each failed attempt |
| `LLM_MAX_RETRIES` | `4` | Retries for temporary Gemini API errors |

## Usage

```bash
python main.py "Find the 3 highest-paid employees and calculate their average salary"
python main.py                      # interactive mode
python main.py --max-steps 4 "..."  # custom step limit
python main.py --quiet "..."        # print only the final answer
python main.py --list-models        # models available for your API key
```

Example tasks: *"Sab se zyada sales wala product kaun sa hai aur uska percentage kya hai?"*, *"Read sales.csv, compute total revenue and add 18% GST"*, *"Read notes.txt, find the expansion city and search its population"*.

## Logging

Every run writes `logs/<label>_<timestamp>_<id>.jsonl`, one JSON object per line.

| Event | Meaning |
|---|---|
| `run_start`, `run_end` | Task, model, limits; final status, steps, duration, answer |
| `llm_response` | Latency, finish reason, token usage, requested tools |
| `thought` | Model thinking summary or narration before a tool call |
| `tool_call` | Tool name and arguments |
| `validation_error` | Rejected arguments and the reason |
| `tool_attempt`, `retry_wait` | Each attempt, its error and the backoff delay |
| `tool_result` | Output or error, attempts, duration |
| `loop_guard`, `step_limit_reached`, `error` | Guards and failures |

## Testing

### Offline suite (no API key, no internet)

```bash
pytest -q
```

32 tests drive the real agent loop with a scripted fake LLM: calculator edge cases, SQL injection and destructive statements, path traversal, self-correction after invalid arguments, unknown tools, retry-then-success, retry exhaustion, no retry for deterministic errors, step limit, loop guard, LLM failure, empty responses, log content, and a guarantee that `DELETE` never changes the database.

### Live suite (13 multi-step tasks)

```bash
python -m tests.run_tests                  # all tasks
python -m tests.run_tests --only 1 5 9     # selected tasks
python -m tests.run_tests --delay 10       # wait 10 s between tasks (rate limits)
```

Results are written to `results/test_results.md` and `.json`, and each task keeps its own trace in `logs/`. Expected values are computed from the data at check time.

| 2 | Total revenue from `sales.csv` + 18% GST | file_reader, calculator | Correct total with GST |
| 3 | Best-selling product and its percentage share | db_query, calculator | Product and percentage |
| 4 | Expansion city from `notes.txt`, then its population | file_reader, web_search | City found, web search used |

## Known failures and limitations

| Issue | Cause | Handling |
|---|---|---|
| HTTP 429 `RESOURCE_EXHAUSTED` stopped the suite | Gemini free tier allows only 20 requests per day per model; a full suite needs 50-80 | Per-day quota errors are not retried and the runner stops early. Switch `GEMINI_MODEL`, run tasks over several days with `--only`, or enable billing |
| 404 "model no longer available" | `gemini-2.5-flash` was scheduled for shutdown on 16 Oct 2026 | Model is configurable; use `--list-models` |
| Web-search task used 8 of 8 steps (158 s) | Several overlapping searches and cross-checking | Loop guard blocks exact repeats; raise `MAX_STEPS` or ask for a single search |
| Live refusals came from the model, not from code | The model followed the system-prompt rules before any tool call | Code-level guards are verified offline by forcing the forbidden call |
| Noisy `thought` text | It is Gemini's thinking summary, not raw chain of thought | Full text kept in the JSONL log |
| `%` in the calculator | `%` is modulo, not a percentage | Tool description tells the model to use `0.15 * x` |

Other limits: results depend on the model and on live web search, so repeated runs can differ; pass/fail checks look for the expected number and tool usage in the answer text.

## Troubleshooting

| Problem | Fix |
|---|---|
| `getaddrinfo failed` during `pip install` | DNS problem: set DNS to `8.8.8.8` / `1.1.1.1`, run `ipconfig /flushdns` |
| `GEMINI_API_KEY is missing` | `.env` must be in the project root with `GEMINI_API_KEY=your_key` (no quotes or spaces) |
| `404 ... model ... not found` | Run `python main.py --list-models` and set `GEMINI_MODEL` |
| `429 ... quota` | Wait, switch model, or enable billing |
